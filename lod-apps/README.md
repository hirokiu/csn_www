# LOD applications

LODを利用した検索・可視化サービスの配置情報を管理します。公開用ファイルは htdocs/lod/<application>/ に置き、manifest.json にアプリの状態と公開パスを登録します。

## 配置規則

- 1サービスにつき1ディレクトリとする
- ブラウザーからの起点は各ディレクトリの index.html とする
- CSS、JavaScript、画像はアプリのディレクトリ内に閉じる
- /sparql をSPARQLエンドポイントの既定パスとする
- オントロジーURIは https://seismic.balog.jp/ontology/jp-earthquake.ttl# を使用する
- APIキーや認証情報をビルド成果物へ埋め込まない
- JavaScript依存関係のソースマップに秘密情報やローカルパスを含めない

## 別リポジトリのアプリ

クエリビルダーなど別リポジトリで開発するアプリは、ソースコード、テスト、依存関係、CIを元リポジトリで管理します。完成後に地震LOD向けの設定を行い、公開方式を決定してからこのサイトへ配置します。

アプリは次の条件を満たす必要があります。

- サブパスから配信できること
- ベースパスを /lod/<application>/ に設定できること
- 相対URLまたは設定可能な公開URLを使用すること
- モバイル表示に対応すること
- 日本語・英語を切り替えられること
- SPARQLエンドポイントをビルド時または実行時設定にできること

オントロジー・クエリビルダーの予約パスは /lod/query-builder/ です。QuokkaGraphの開発中はリポジトリ統合や本番proxy設定を行わず、地震LOD対応版が完成してから配置します。
